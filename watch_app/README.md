# Watch App + iPhone Relay — Source Scaffold

These are Swift source files meant to be dropped into an Xcode project
(watchOS app target + a paired iOS companion app target). They are **not**
a buildable Xcode project by themselves — Xcode project files, asset
catalogs, and entitlements need to be set up in Xcode first. This scaffold
gives you the actual capture logic so you're not starting from a blank file.

## Setup in Xcode

1. Create a new Xcode project → **watchOS App** template, which auto-generates
   a paired iPhone app target. Name it (e.g. `EMTReportAssistant`).
2. Enable capabilities on the watch target: **Microphone** (for dictation) and
   **Speech Recognition** usage description in `Info.plist`.
3. Enable **Background Modes → Uses Bluetooth LE accessories** (or just rely on
   the default Watch Connectivity, which uses Bluetooth automatically) on both
   targets.
4. Drop the files below into their respective targets:
   - `WatchApp/*.swift` → the watchOS app target
   - `iOSRelayApp/*.swift` → the iOS (iPhone) app target
5. Set `PhoneConnectivityManager.backendBaseURL` to wherever your FastAPI
   backend is running (e.g. `http://<your-laptop-ip>:8000` on the same
   wifi/hotspot for a demo, or a Bluetooth PAN address per CLAUDE.md's
   demo-reliability fallback).

## What's included

- **WatchApp**: capture-only UI — one-tap timestamps, vitals quick-entry,
  and voice dictation using Apple's on-device Speech framework. No editing
  or report review happens here, per CLAUDE.md's design principles.
- **iOSRelayApp**: receives captures from the watch over Watch Connectivity
  (Bluetooth), queues them locally if there's no connectivity to the
  backend, and syncs them via HTTP once the backend is reachable.

## Not included in this scaffold

Xcode project files (`.xcodeproj`), asset catalogs, app icons, and
entitlement files — these need to be generated by Xcode itself when you
create the project, since they're mostly binary/generated content.
